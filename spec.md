# FlashCards — Product Spec

Версия: 0.3 (draft, на подтверждении)
Дата: 2026-05-22

## Одно предложение

Веб-приложение для создания, изучения и шаринга карточек со spaced
repetition, с аккаунтами и синхронизацией прогресса между устройствами.

## Аудитория

Разработчики и студенты СНГ и международная (без РФ), изучающие
технические темы (ru/en).

## Стек

- Frontend: Vue 3 + TypeScript + Vite + Tailwind CSS, SPA, PWA
- Архитектура фронта: Feature-Sliced Design v2.1
  (app / pages / widgets / features / entities / shared)
- Backend: Go (Echo), layered handler / service / repo
- БД: PostgreSQL
- Хранилище медиа: S3-совместимое
- Хостинг: провайдер-нейтрально (всё в Docker), выбор отложен до деплоя

## MVP v1 — обязательный функционал

- [ ] Базовая авторизация: регистрация и вход email + пароль, JWT-сессии
- [ ] CRUD колод: название, описание, теги, приватная/публичная
- [ ] CRUD карточек: только тип Basic (front/back текст)
- [ ] Одно изображение на стороне карточки (front и/или back)
- [ ] SRS — алгоритм из прототипа (SM2-подобный)
- [ ] Прогресс хранится на бэкенде, синхронизация между устройствами
- [ ] Страница прогресса: графики (статусы карт, прогресс по тегам, активность по дням)
- [ ] Импорт: CSV, JSON
- [ ] Экспорт: CSV, JSON
- [ ] PWA: установка, offline-изучение уже загруженных колод
- [ ] Шаринг колоды по ссылке (read-only, без авторизации у получателя)
- [ ] Внутренний REST API (для собственного фронта)

## Reference implementation (шаг 5 плейбука)

Канонический паттерн — реализуется первым, медленно, на L2. Узкий
scope: задаёт шаблон, который остальные фичи копируют по Сценарию C.

> Пользователь регистрируется, входит, создаёт колоду, видит список
> своих колод.

Прогоняет каждый слой один раз: backend handler → service → repo → DB,
JWT-middleware; frontend page → entity → shared/api, router guard, Pinia.
Карточки, SRS, импорт/экспорт, шаринг, графики — каждая отдельной
фичей по Сценарию C, копирует этот шаблон.

## Non-goals v1 (явно НЕ делаем)

- НЕТ: OAuth (Google/Яндекс) → v2, в v1 только email + пароль
- НЕТ: refresh-токены → v2, в v1 один JWT (~7 дней)
- НЕТ: типы карточек Cloze, Multiple-choice, Image-occlusion → v2
- НЕТ: экспорт/импорт Anki .apkg → отдельный подпроект, не v1
- НЕТ: кастомный CSS на карточку → v2, требует sandbox (XSS-риск)
- НЕТ: rich-media редактор — только одно изображение на сторону
- НЕТ: публичный API для сторонних клиентов → v2
- НЕТ: монетизация, подписки
- НЕТ: нативные iOS/Android
- НЕТ: коллаборация (несколько авторов одной колоды)
- НЕТ: AI-генерация карточек
- НЕТ: восстановление пароля по email → v2 (требует email-сервиса)

## Приватность

Аудитория без РФ — 152-ФЗ не применяется, жёсткой локализации данных
нет. Перед публичным запуском нужна стандартная политика конфиденци-
альности. Хранимые персданные минимизированы: только email и bcrypt-
хэш пароля.

## Контекст-наследие

Прототип `flashcards-app.jsx` — UX-референс (палитра, флип, layout,
SRS-формула). Кодом не мигрируется: это React + Claude-artifact storage
API, как веб-приложение никогда не запускался. SRS-функция и дизайн-
токены копируются; storage-хук — мёртвый.
