# Go с нуля — ELI5

Этот документ объясняет Go с самого начала, без допущений. Если знаешь
чуть-чуть JavaScript — этого хватит. Читай по порядку, не перескакивай.

Сначала прочитай ЭТОТ файл. Потом `go-walkthrough.md` — там тур по
реальным файлам проекта, и термины оттуда уже будут знакомы.

---

## 1. Что такое Go и что значит «компилируется»

JavaScript работает так: ты пишешь текст, браузер (или Node) читает его
и выполняет на ходу, строчку за строчкой. Текст программы нужен всегда —
без него ничего не запустится.

Go работает иначе. Ты пишешь текст, потом запускаешь **компилятор** —
специальную программу, которая один раз переводит весь твой текст в
готовый файл-программу (набор инструкций для процессора). Дальше
запускается уже этот файл. Сам текст больше не нужен.

Аналогия. JavaScript — это переводчик-синхронист: он переводит твою речь
вживую, каждый раз заново. Go-компилятор — переводчик, который один раз
перевёл книгу и напечатал тираж; дальше все читают готовый перевод.

Что это даёт:
- Программа работает быстро — процессор сразу исполняет готовые инструкции.
- Ошибки в типах ловятся **при компиляции**, то есть до запуска. Если ты
  написал бессмыслицу, компилятор откажется собирать программу и покажет,
  где. В JS такая ошибка вылезла бы уже у пользователя.

Команды:
- `go run ./...` — скомпилировать и сразу запустить (удобно при разработке).
- `go build ./...` — собрать файл-программу.
- `go test ./...` — собрать и прогнать тесты.

## 2. Самая маленькая программа

```go
package main

func main() {
    println("привет")
}
```

Разберём каждое слово:

- `package main` — каждый файл Go начинается со слова `package` и имени.
  `main` — особое имя, оно означает «это запускаемая программа».
- `func main()` — `func` значит «функция». `main` — тоже особое имя:
  с этой функции начинается выполнение. Программа запустилась → Go находит
  `func main` → выполняет всё, что внутри `{ }`.
- `{ }` — фигурные скобки очерчивают «тело»: что входит в функцию.
  Точно как в JavaScript.

## 3. Переменные и типы

Переменная — это коробка с именем, в ней лежит значение.

В JavaScript у коробки нет жёсткого типа: `let x = 5`, потом можно
`x = "текст"` — и ничего не сломается на этом месте.

В Go у каждой коробки **жёсткий тип**. Коробка для чисел никогда не
примет строку. Это проверяет компилятор.

```go
var age int = 30          // коробка age, тип int (целое число), значение 30
var name string = "Аня"   // коробка name, тип string (строка)
```

Формула: `var имя тип = значение`.

Есть короткая форма — её используют внутри функций почти всегда:

```go
age := 30        // создай коробку age, положи 30, тип определи сам
name := "Аня"    // тип сам определится как string
```

`:=` означает «создай новую коробку и положи значение; тип выведи
автоматически». `30` — целое число, значит тип будет `int`. Результат
тот же, что у длинной формы, просто короче.

Базовые типы, которые встретятся:
- `int` — целое число (`30`, `-7`, `0`)
- `string` — строка (`"привет"`)
- `bool` — истина или ложь (`true` / `false`)
- `float64` — дробное число (`3.14`)
- `[]byte` — последовательность байт (понадобится для паролей)

**Нулевое значение.** Если создать коробку без значения — `var age int` —
там не «undefined», там `0`. У строки — `""`, у bool — `false`. Go никогда
не оставляет коробку пустой: всегда кладёт «ноль» нужного типа.

## 4. Функции

```go
func add(a int, b int) int {
    return a + b
}
```

- `func` — объявляем функцию. `add` — её имя.
- `(a int, b int)` — что функция **принимает**: коробку `a` типа int и
  коробку `b` типа int.
- `int` сразу после скобок — что функция **возвращает**: одно целое число.
- `return a + b` — отдать результат наружу.

Вызов: `sum := add(2, 3)` — в `sum` окажется `5`.

Если несколько аргументов одного типа подряд, тип можно написать один раз:
`func add(a, b int) int`.

### Главная странность: несколько возвращаемых значений

В JavaScript функция возвращает что-то одно (или объект/массив, чтобы
упаковать несколько).

В Go функция может вернуть **несколько значений сразу**:

```go
func divide(a, b int) (int, bool) {
    if b == 0 {
        return 0, false     // результат 0 и признак «не получилось»
    }
    return a / b, true      // результат деления и признак «получилось»
}
```

Принимаем оба значения:

```go
result, ok := divide(10, 2)   // result = 5, ok = true
```

Этот приём используется в Go повсюду — особенно для ошибок (раздел 5).

## 5. Ошибки — самое непривычное

В JavaScript: что-то сломалось → `throw`, а ловишь через `try/catch`.
Ошибка «летит» вверх по коду сама, пока её не поймают.

В Go **нет** `throw` и **нет** `try/catch`. Ошибка — это обычное
значение, которое функция **возвращает** как ещё один результат.

Договорённость всего языка: если функция может не справиться, она
возвращает последним значение типа `error`.

```go
func readFile(name string) (string, error) {
    // ... вернёт (содержимое, nil) при успехе
    // ... или ("", ошибку) при неудаче
}
```

`error` — особый тип с двумя состояниями:
- `nil` — «ошибки нет, всё хорошо». `nil` вообще означает «пусто, ничего».
- не `nil` — внутри лежит описание, что пошло не так.

Поэтому после **каждого** такого вызова идёт проверка:

```go
content, err := readFile("data.txt")
if err != nil {          // если ошибка не пустая...
    return err           // ...не продолжаем, передаём ошибку выше
}
// если дошли сюда — ошибки не было, content корректен
```

Строчку `if err != nil { ... }` ты увидишь в Go-коде сотни раз. Это и
есть «обработка ошибок» по-Go. Выглядит громоздко — зато ошибку
невозможно случайно пропустить: она лежит прямо у тебя в руках как
значение, её видно.

Почему так сделано: всегда явно видно, какая функция может упасть и где
именно это обрабатывается. Ничего не «летит» незаметно сквозь код.

## 6. Структуры (struct) — свои типы

Часто нужно хранить несколько связанных значений вместе. Например, у
пользователя есть id, email и дата регистрации.

В JavaScript это объект: `{ id, email }`.

В Go ты сначала описываешь **чертёж** — какие у такой коробки отделения:

```go
type User struct {
    ID    string
    Email string
}
```

Читается: «объявляю новый тип с именем `User`; это структура с
отделениями `ID` (строка) и `Email` (строка)».

Это пока только чертёж, не значение. Теперь создаём значение по чертежу:

```go
u := User{ID: "abc", Email: "a@b.com"}
```

Доступ к отделению — через точку: `u.Email` вернёт `"a@b.com"`.

Структура похожа на TypeScript-`interface` для объекта, но это
конкретный тип, по которому реально создают значения.

## 7. Указатели — самое сложное. Читай медленно.

Этого в JavaScript почти нет в явном виде. Разберём очень подробно.

### Коробки и адреса

Переменная — это коробка в памяти компьютера. У каждой коробки есть
**адрес** — как у дома или у ячейки в камере хранения.

```go
age := 30
```

Есть коробка со значением `30`. У неё есть адрес — например, условно
«ячейка №7». Обычно ты работаешь со значением и про адрес не думаешь.

### Что такое указатель

**Указатель — это коробка, в которой лежит не значение, а адрес другой
коробки.**

Аналогия. Вместо того чтобы таскать с собой тяжёлый чемодан, ты носишь
бумажку: «чемодан в камере хранения, ячейка 7». Бумажка — это указатель.
Чемодан — реальное значение.

Два оператора:
- `&age` — «дай адрес коробки age» (взять бумажку с номером ячейки).
  Значок `&` означает «адрес чего-либо».
- `*p` — «иди по адресу из p и возьми или положи значение там» (сходить
  по бумажке к ячейке). Значок `*` означает «значение по адресу».

```go
age := 30
p := &age       // p — указатель: в нём лежит адрес коробки age
println(*p)     // *p — идём по адресу, берём значение → напечатает 30
*p = 99         // идём по адресу и КЛАДЁМ туда 99
println(age)    // age теперь 99 — мы изменили ту же самую коробку
```

Тип такой переменной `p` записывается как `*int` — «указатель на int».

### Зачем указатели вообще нужны — две причины

**Причина 1 — изменить оригинал, а не копию.**

В Go, когда ты передаёшь значение в функцию, функция получает **копию**.

```go
func setToZero(x int) {
    x = 0           // меняем КОПИЮ, оригинал не трогаем
}

n := 5
setToZero(n)
println(n)          // всё ещё 5 — оригинал не изменился
```

Чтобы функция изменила **оригинал**, передай ей адрес:

```go
func setToZero(x *int) {    // принимает указатель на int
    *x = 0                  // идём по адресу и кладём 0 в оригинал
}

n := 5
setToZero(&n)               // передаём АДРЕС коробки n
println(n)                  // теперь 0 — оригинал изменён
```

**Причина 2 — не копировать большие структуры.**

Если структура большая (много полей), копировать её при каждой передаче
в функцию — лишняя работа. Передаёшь указатель (`*User`) — копируется
только маленький адрес, а не вся структура целиком.

### Где это встречается в нашем проекте

- `func NewTokenManager(...) *TokenManager` — возвращает указатель. Значит
  все, кто его получил, работают с **одним и тем же** менеджером, а не с
  отдельными копиями.
- `&User{...}` — «создай структуру User и дай мне её адрес».
- `&body` в `c.ShouldBindJSON(&body)` — «вот адрес моей пустой коробки
  body, запиши результат разбора прямо туда». Функция должна изменить
  оригинал → ей нужен адрес.

Если не «щёлкнуло» сразу — это нормально. Правило на первое время:
- видишь `*Тип` в коде — читай как «ссылка на Тип»;
- видишь `&x` — читай как «берём адрес x, чтобы кто-то изменил оригинал
  или чтобы не копировать большое».

## 8. Методы — функции, привязанные к структуре

Обычная функция существует сама по себе: `add(2, 3)`.

Метод — это функция, «приклеенная» к типу. Её вызывают через точку от
значения: `u.ЧтоТоСделать()`.

```go
type TokenManager struct {
    secret []byte
}

func (m *TokenManager) Issue(userID string) string {
    // ...
}
```

- Кусок `(m *TokenManager)` **перед именем функции** — это «получатель»
  (receiver). Именно он превращает функцию в метод: «это метод типа
  `TokenManager`».
- `m` — имя, под которым внутри метода доступна сама структура. Похоже на
  `this` в JavaScript, но имя выбираешь ты сам (обычно одна короткая буква).
- `*TokenManager` — получатель является указателем: метод работает с тем же
  экземпляром структуры, а не с копией. Это стандартный выбор.
- Вызов: `token := manager.Issue("user-1")`.

Зачем нужны методы: группировать поведение вокруг данных. «У `TokenManager`
есть умение `Issue`».

### Конструкторы

В Go **нет** ключевого слова `constructor` и нет `new`, как в классах
других языков.

Вместо этого договорённость: пишут обычную функцию с именем `NewЧтоТо`,
которая создаёт структуру и возвращает её.

```go
func NewTokenManager(secret string) *TokenManager {
    return &TokenManager{secret: []byte(secret)}
}
```

`NewTokenManager("мой-секрет")` — получил готовый менеджер. Это просто
функция с договорным именем `New...`, никакой особой магии языка тут нет.

## 9. Интерфейсы — «что умеет», а не «что это»

Самая мощная и самая непривычная вещь в Go.

Интерфейс — это **список умений** (методов), без их реализации.

```go
type Greeter interface {
    Greet() string
}
```

Читается: «`Greeter` — это что угодно, у чего есть метод `Greet`,
возвращающий строку».

И вот **главное отличие от TypeScript**:

- TypeScript: `class Dog implements Greeter` — надо **явно написать**
  слово `implements`, объявить «я Greeter».
- Go: писать ничего не надо. Если у твоего типа **есть** метод
  `Greet() string` — он **автоматически** считается `Greeter`. Тип и
  интерфейс могут вообще ничего не знать друг о друге.

Аналогия. Интерфейс «Умеющий летать» = «тот, у кого есть метод
`Летать()`». Птица, самолёт, дрон — никто из них не записывался в клуб
«Умеющие летать», но все туда подходят, потому что у всех есть это умение.

### Зачем это в нашем проекте

`AuthService` (логика регистрации/входа) хочет «кого-то, кто умеет
сохранять и искать пользователей». Он объявляет интерфейс
`UserRepository` — список из трёх методов: `Create`, `FindByEmail`,
`FindByID`.

- В работающей программе туда передают `UserRepo` — настоящий, с
  PostgreSQL.
- В тестах туда передают `fakeUserRepo` — поддельный, хранит данные в
  `map` (это как объект-словарь) прямо в памяти.
- `AuthService` **не видит разницы**: обоим достаточно «иметь нужные три
  метода».

Это и позволяет тестировать логику без базы данных: подменяешь реализацию
на поддельную, а сам проверяемый код не меняется ни на строчку.

## 10. Пакеты и папки (коротко)

- Каждый файл начинается со строки `package имя`.
- Все файлы в одной папке = один пакет. Внутри пакета файлы видят функции
  и типы друг друга без всяких импортов.
- Чтобы использовать другой пакет — `import "путь"`, затем обращение
  `пакет.Функция()`.
- **Заглавная** первая буква имени (`User`, `Load`) — видно из других
  пакетов (аналог `export` в JS).
- **Строчная** первая буква (`user`, `env`) — видно только внутри своего
  пакета (приватное).
- Папка с именем `internal/` — особая: пакеты внутри неё может
  использовать только код этого же проекта.
