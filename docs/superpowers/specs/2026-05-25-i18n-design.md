# i18n Design — DéjàKnew

**Date:** 2026-05-25  
**Status:** Approved  
**Scope:** Frontend UI strings + backend emails/notifications  
**Languages:** Russian (ru), English (en)  
**Branch:** `feature/i18n`

---

## Goals

- Translate all static UI strings in the Vue 3 web app (ru/en)
- Localize backend-sent emails and notifications
- Auto-detect locale from browser; user can override via switcher
- Store locale preference in `localStorage` (frontend) and `users.locale` DB column (backend)

## Non-Goals

- Translating user-created flashcard content
- Right-to-left (RTL) layout support
- More than 2 languages in this phase
- Date/number formatting beyond what vue-i18n provides out of the box

## Frontend

### Library

`vue-i18n` v9 — Composition API mode (`createI18n({ legacy: false })`).

### Locale Detection Order

1. `localStorage.getItem('locale')` — user's saved preference
2. `navigator.language.split('-')[0]` — browser language
3. Default: `'en'`

Supported values: `'ru'` | `'en'`. Anything else falls back to `'en'`.

### File Structure

```
web/src/shared/config/
  i18n.ts               — createI18n instance + detection logic
  locales/
    en.json             — English message catalog
    ru.json             — Russian message catalog
  index.ts              — re-exports i18n instance

web/src/shared/ui/
  LocaleSwitcher.vue    — ru/en toggle, saves to localStorage

web/src/shared/api/

web/src/app/
  main.ts               — app.use(i18n)
```

## Backend

### Library

`github.com/nicksnyder/go-i18n/v2` — file-based TOML catalogs, loaded at startup.

### File Structure

```
api/internal/i18n/
  i18n.go               — Bundle init, NewLocalizer(lang) helper func
  locales/
    en.toml             — English message catalog
    ru.toml             — Russian message catalog
```

### TOML Format

```toml
[WelcomeEmailSubject]
description = "Subject line for welcome email"
one = "Welcome to DéjàKnew!"

[WelcomeEmailBody]
description = "Body of welcome email"
one = "Hi {{.Name}}, your account is ready."
```

### Locale Resolution

- **Request-scoped** (API handlers): middleware reads `Accept-Language` header → sets `locale` on Gin context
- **Background/async** (email sends): read `user.Locale` from DB — not tied to an HTTP request

### DB Change

`users` table: add `locale VARCHAR(5) NOT NULL DEFAULT 'en'`.

- Set on registration: frontend sends `locale` field in register request body (same value as detected locale)
- Registration API handler reads `locale` from body, writes to `users.locale`
- Updateable via user settings (future)

### Middleware

`api/internal/handler/middleware/locale.go`:
- Parses `Accept-Language` header
- Extracts primary language tag (`ru`, `en`)
- Falls back to `'en'` if unsupported
- Injects into Gin context: `c.Set("locale", lang)`

### Email Audit

All email-sending call sites must be identified and updated to pass a `*i18n.Localizer` during implementation. Minimum expected: welcome/registration email.

## Locale Switching Flow (End-to-End)

```
User clicks ru/en toggle
  → LocaleSwitcher sets locale.value = 'ru'
  → saves to localStorage('locale', 'ru')
  → vue-i18n reactively updates all t() calls in UI
  → shared/api/client.ts sends Accept-Language: ru on every request
  → Go middleware reads header, injects locale into ctx
  → email helpers use user.Locale (stored in DB) for async sends
```

## Out of Scope (This Phase)

- Ukrainian or other languages
- Server-side rendering (not in stack)
- Pluralization beyond simple cases
- Currency/date locale formatting (can layer on later via vue-i18n built-ins)
